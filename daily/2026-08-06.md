# Step 3 — Coding Practice

### Exercise 1: Line Breakpoints & Live Variable Stepping (Easy)
* **Objective**: Pause execution with line breakpoints and step through loop iterations.
* **Difficulty**: Easy
* **Expected Outcome**:
  1. Create `DebugLoop.java` under `scratch/`:
     ```java
     public class DebugLoop {
         public static void main(String[] args) {
             int totalSum = 0;
             for (int i = 1; i <= 10; i++) {
                 totalSum += i; // SET BREAKPOINT ON THIS LINE!
             }
             System.out.println("Final Sum: " + totalSum);
         }
     }
     ```
  2. Set a line breakpoint on `totalSum += i;`.
  3. Start Debugging (`F5`).
  4. Use Step Over (`F10`) to step through loop iterations. Watch `i` and `totalSum` update live in the "VARIABLES" panel.

### Exercise 2: Conditional Breakpoints & Watch Expressions (Medium)
* **Objective**: Intercept specific runtime states using conditional breakpoints and evaluate dynamic expressions.
* **Difficulty**: Medium
* **Expected Outcome**:
  1. Create `TransactionDebugger.java`:
     ```java
     public class TransactionDebugger {
         public static void main(String[] args) {
             double[] transactions = { 45.0, 120.5, 12.0, 999.0, 50.0, 1500.0, 30.0 };
             double balance = 1000.0;
             for (double tx : transactions) {
                 balance += tx; // SET CONDITIONAL BREAKPOINT HERE!
             }
         }
     }
     ```
  2. Right-click the breakpoint gutter on `balance += tx;` $\rightarrow$ Select **Edit Breakpoint** $\rightarrow$ **Expression**.
  3. Set condition: `tx > 500.0`.
  4. Add a Watch Expression in the WATCH panel: `balance + tx`.
  5. Start Debugging (`F5`). Verify that execution pauses ONLY when `tx` is `999.0` and `1500.0`, skipping small transactions automatically!
* **Hints**: Conditional breakpoints evaluate a boolean expression; if true, execution pauses.
* **Common Mistakes**: Manually stepping through hundreds of array elements instead of setting a conditional breakpoint.

# Step 7 — Engineering Insight

### Print Debugging vs. Interactive IDE Debugging
Why do senior engineers avoid "print debugging" (`System.out.println`)?

| Feature | Print Debugging (`println`) | Interactive Debugger |
| :--- | :--- | :--- |
| **Code Hygiene** | Pollutes source code with temporary logs | Zero code changes required |
| **Execution Flow** | Requires continuous recompilation & runs | Pauses execution live on demand |
| **State Inspection** | Shows only pre-selected printed variables | Inspects the entire heap object graph |
| **Loop Debugging** | Dumps thousands of log lines into console | Conditional Breakpoints target exact bugs |
| **Expression Testing** | Static output | Dynamically evaluates expressions in WATCH |
