# Step 3 — Coding Practice

### Exercise 1: Command Argument Dispatcher (Easy)
* **Objective**: Parse and dispatch string command arguments to separate handler methods.
* **Difficulty**: Easy
* **Expected Outcome**:
  1. Create `SimpleCliDispatcher.java` under `scratch/`:
     ```java
     public class SimpleCliDispatcher {
         public String dispatch(String[] args) {
             if (args == null || args.length == 0) {
                 throw new IllegalArgumentException("No command provided. Usage: add|list|complete");
             }
             String action = args[0].trim().toUpperCase();
             switch (action) {
                 case "ADD":
                     if (args.length < 2) throw new IllegalArgumentException("Task description required for ADD.");
                     return "Executing ADD: " + args[1];
                 case "LIST":
                     return "Executing LIST tasks";
                 case "COMPLETE":
                     if (args.length < 2) throw new IllegalArgumentException("Task ID required for COMPLETE.");
                     return "Executing COMPLETE for ID: " + args[1];
                 default:
                     throw new IllegalArgumentException("Unknown command: " + action);
             }
         }
     }
     ```
  2. Write a JUnit 5 test `SimpleCliDispatcherTest.java` verifying that `"ADD"` and `"LIST"` dispatch cleanly, while empty args throw `IllegalArgumentException`.

# Step 7 — Engineering Insight

### Separating Console I/O from Domain Logic
Why is burying `Scanner scanner = new Scanner(System.in)` and `System.out.println()` inside your domain business classes a severe anti-pattern?

1. **Testability**: If `TaskManager.addTask()` prompts `System.in` for user input, you cannot run automated JUnit unit tests on it! You would have to manually type inputs into the console every time tests run.
2. **Reusability**: If you later want to turn your Task Tracker into a Web API or GUI app, a domain class tied to `System.out.println()` cannot be reused without rewriting it completely.

**Senior Rule**: Keep domain classes pure. Accept parameters directly in method arguments, and handle console I/O exclusively inside a lightweight CLI entry point class.

# Step 8 — Open Source Connection

In tools like **Git CLI (`git`) & Apache Maven (`mvn`)**:
* When you run `git commit -m "message"`, the `git` binary's CLI parser converts the `-m` flag into a `CommitOptions` value object.
* It passes `CommitOptions` to the underlying domain engine (`GitRepository`), which contains zero console printing logic, allowing Git to be embedded inside IDEs (like VS Code or IntelliJ) effortlessly.
