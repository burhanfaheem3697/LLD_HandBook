# Step 3 — Coding Practice

### Exercise 1: IDE Navigation & Call Hierarchy Traversal (Easy)
* **Objective**: Practice traversing class calls and navigating back and forth across package boundaries.
* **Difficulty**: Easy
* **Expected Outcome**:
  1. Open your handbook project in your IDE.
  2. Navigate to `OrderProcessorTest.java` from Module 2.
  3. Place cursor on `processOrder()` and press **Go to Definition** (`F12`). Notice how the IDE jumps across package boundaries to `OrderProcessor.java`.
  4. Press **Find All References** (`Shift+F12`). Observe the list of all caller sites.
  5. Press **Navigate Back** (`Alt + Left Arrow` in VS Code / `Ctrl + Alt + Left` in IntelliJ) to return seamlessly to your previous cursor position.

### Exercise 2: Auditing JDK ArrayList Growth Mechanics (Medium)
* **Objective**: Audit an unfamiliar core JDK class by tracing its internal execution chain.
* **Difficulty**: Medium
* **Expected Outcome**:
  1. Open JDK's `java.util.ArrayList` source file in your IDE (`Ctrl + Click` on `ArrayList`).
  2. Locate `public boolean add(E e)`.
  3. Use `Go to Definition` (`F12`) to trace the call down to `add(e, elementData, s)`.
  4. Trace further down to `grow(int minCapacity)` and `newCapacity(int minCapacity)`.
  5. Record the internal growth call tree in your notes:
     `add()` $\rightarrow$ `add(e, elementData, s)` $\rightarrow$ `grow()` $\rightarrow$ `newCapacity()` $\rightarrow$ `Arrays.copyOf()`.
  6. Document in your notes: *"JDK ArrayList grows its internal element array capacity by ~50% (`oldCapacity + (oldCapacity >> 1)`) when full."*
* **Hints**: Use `F12` to jump to internal helper methods and `Alt + Left` to navigate back.
* **Common Mistakes**: Getting bogged down reading private comments or utility checks; focus on the primary execution branch!

# Step 7 — Engineering Insight

### Systematic Code Reading & Entry Point Discovery
How do senior engineers audit a 500,000-line unfamiliar production codebase without feeling lost?

1. **Locate Public Entry Points**: Start at public facades, REST controllers, or CLI `main()` methods. Ignore private helper implementations initially.
2. **Read Test Suites First**: Automated unit tests (`*Test.java`) are executable specifications. They show valid inputs, expected outputs, and error handling contracts without forcing you to wade through internal code.
3. **Trace Call Trees, Not Random Lines**: Use IDE Call Hierarchy tools (`Shift+F12`) to trace how data flows from entry points down to core domain entities.
4. **Sketch Mental Models**: Draw quick box-and-arrow sketches to capture object relationships as you read.
