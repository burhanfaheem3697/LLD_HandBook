     * `PublicFacade.java` (`public class PublicFacade { public String getInfo() { return "Public"; } }`)
     * `InternalHelper.java` (`class InternalHelper { String getSecret() { return "Secret"; } }` — note package-private visibility!)
  2. Under `scratch/maven-demo/src/main/java/com/handbook/client/`, create `ClientApp.java`.
  3. Inside `ClientApp`, try instantiating `PublicFacade` (works!). Then try instantiating `InternalHelper`. Observe the compilation error: `InternalHelper is not public in com.handbook.internal; cannot be accessed from outside package`.

### Exercise 2: Package-Private Facade Pattern (Medium)
* **Objective**: Hide internal helper implementations behind a public package facade.
* **Difficulty**: Medium
* **Expected Outcome**:
  1. Create package `com.handbook.security`.
  2. Create package-private class `PasswordEncryptor` (no `public` keyword) with method `String encrypt(String raw)`.
  3. Create `public class SecurityService` with a public method `boolean registerUser(String user, String rawPassword)`. Internally, `SecurityService` uses `PasswordEncryptor`.
  4. Create a test class in `src/test/java/com/handbook/client/ClientTest.java`. Verify that `ClientTest` can call `SecurityService.registerUser(...)`, but cannot directly access `PasswordEncryptor`.
* **Hints**: Omit the `public` modifier on the class header to make it package-private: `class PasswordEncryptor { ... }`.
* **Common Mistakes**: Defaulting to adding `public` to every class header without considering whether external packages need direct access.

# Step 7 — Engineering Insight

### Package-Private Scope as an Architecture Boundary
Why is default (package-private) visibility one of Java's most underutilized features?
* **Public API Sprawl**: If every class in your project is `public`, any external package can import and depend on your internal helper classes. If you later try to refactor or remove a helper class, you risk breaking external downstream callers.
* **Encapsulation Boundary**: By keeping helper classes package-private (no `public` modifier), they are accessible only to classes within the exact same Java package. The package acts as a micro-subsystem: a clean public facade (`public`) on the outside, with private engine parts (`package-private`) hidden inside.

# Step 8 — Open Source Connection

In the **Java Development Kit (JDK)**:
* In `java.util`, classes like `Collections` expose public static factory methods like `Collections.unmodifiableList(...)`.
* The actual wrapper class `java.util.Collections$UnmodifiableList` is package-private! You cannot instantiate `new UnmodifiableList()` directly; you are forced to use the public factory facade.
