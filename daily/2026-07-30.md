# Step 3 — Coding Practice

### Exercise 1: Building a Standard Directory Layout Skeleton (Easy)
* **Objective**: Construct a Maven Standard Directory Layout and POM file manually from scratch.
* **Difficulty**: Easy
* **Expected Outcome**:
  1. Create a scratch directory: `scratch/maven-demo`.
  2. Create standard directories:
     * `src/main/java/com/handbook/demo`
     * `src/main/resources`
     * `src/test/java/com/handbook/demo`
     * `src/test/resources`
  3. Create a minimalist `pom.xml` file inside `scratch/maven-demo`:
     ```xml
     <project xmlns="http://maven.apache.org/POM/4.0.0"
              xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
              xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
         <modelVersion>4.0.0</modelVersion>

         <groupId>com.handbook</groupId>
         <artifactId>maven-demo</artifactId>
         <version>1.0.0-SNAPSHOT</version>
     </project>
     ```

### Exercise 2: Dependency Scoping & Compile Isolation (Medium)
* **Objective**: Configure dependency scope and verify compile-time isolation between production and test code.
* **Difficulty**: Medium
* **Expected Outcome**:
  1. In `scratch/maven-demo/pom.xml`, add the JUnit 5 dependency under `<dependencies>` with `<scope>test</scope>`:
     ```xml
     <dependencies>
         <dependency>
             <groupId>org.junit.jupiter</groupId>
             <artifactId>junit-jupiter-api</artifactId>
             <version>5.9.2</version>
             <scope>test</scope>
         </dependency>
     </dependencies>
     ```
  2. Under `src/test/java/com/handbook/demo/`, create `AppTest.java` importing `org.junit.jupiter.api.Test`.
  3. Under `src/main/java/com/handbook/demo/`, create `App.java`. Try importing `org.junit.jupiter.api.Test` inside `App.java`. Observe that production code under `src/main/java` cannot access `test`-scoped dependencies!
* **Hints**: The `<scope>test</scope>` setting isolates testing tools from production runtime artifacts.
* **Common Mistakes**: Putting test libraries (like JUnit or Mockito) in `compile` scope, inflating production bundle sizes.

# Step 7 — Engineering Insight

### Convention over Configuration & Transitive Dependencies
Build automation tools rely on two foundational software design principles:

1. **Convention over Configuration**: Instead of writing verbose scripts telling the compiler where every single file is, Maven/Gradle define standard conventions (`src/main/java`). By adhering to the convention, zero configuration is required to locate source files.
2. **Transitive Dependency Resolution**: If your application depends on Library A, and Library A depends on Library B (e.g. Jackson JSON parser), Maven automatically downloads both Library A and Library B. The dependency tree guarantees that all required transitive JARs are fetched and placed on the runtime classpath.

# Step 8 — Open Source Connection

In **Spring Boot & Jackson Repositories**:
* Projects use multi-module `pom.xml` files with a parent `pom.xml` managing dependency versions centrally via `<dependencyManagement>`.
* This ensures that all sub-modules (e.g. `spring-boot-starter-web`, `spring-boot-starter-test`) use strictly compatible versions of underlying libraries like Jackson or JUnit.
