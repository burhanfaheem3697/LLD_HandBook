# Today's Objective

* **Today's Focus**: Domain Modeling Foundations: **Value Objects** (immutable, structural attribute equality without identity), **Entities** (persistent identity ID throughout lifecycle), eliminating **Primitive Obsession**, and designing side-effect-free domain methods.
* **Why Today's Work Matters**: Modeling domain concepts (like money, email addresses, or coordinates) using raw `double` or `String` primitives leads to "Primitive Obsession" and invalid state bugs. Value Objects group values and validation rules into type-safe, immutable objects that protect invariants once at construction time.
* **How it Connects to Previous Lessons**: In Lessons 1 & 2 (`P01.M01.L01-L02`), you learned state, identity, and defensive copying. Today, you apply those foundations to master the architectural distinction between Value Objects and Entities.
* **How it Prepares You for Future Lessons**: Prepares you directly for Java 14+ Records (Day 2 of this lesson), Message Passing (`P01.M02.L01`), and Domain-Driven Design aggregates in Phase 2.

### Exercise 2: Designing a Pure Value Object: Money (Medium)
* **Objective**: Build an immutable `Money` value object with currency validation and side-effect-free math.
* **Difficulty**: Medium
* **Expected Outcome**:
  1. Create `Money.java` under `scratch/`:
     ```java
     import java.util.Objects;

     public final class Money {
         private final double amount;
         private final String currency;

         public Money(double amount, String currency) {
             if (amount < 0.0) throw new IllegalArgumentException("Money amount cannot be negative.");
             if (currency == null || currency.trim().isEmpty()) throw new IllegalArgumentException("Currency required.");
             this.amount = amount;
             this.currency = currency.trim().toUpperCase();
         }

         // Side-effect-free operation: Returns a NEW Money instance!
         public Money add(Money other) {
             if (!this.currency.equals(other.currency)) {
                 throw new IllegalArgumentException("Cannot add different currencies: " + this.currency + " vs " + other.currency);
             }
             return new Money(this.amount + other.amount, this.currency);
         }

         public double getAmount() { return amount; }
         public String getCurrency() { return currency; }

         @Override
         public boolean equals(Object o) {
             if (this == o) return true;
             if (!(o instanceof Money)) return false;
             Money money = (Money) o;
             return Double.compare(money.amount, amount) == 0 && Objects.equals(currency, money.currency);
         }

         @Override
         public int hashCode() {
             return Objects.hash(amount, currency);
         }
     }
     ```
  2. Write JUnit 5 test `MoneyTest.java` verifying that adding $50 USD to $100 USD returns a new $150 USD `Money` instance without mutating the original, and adding USD to EUR throws `IllegalArgumentException`.
* **Hints**: Value Objects MUST be `final` and immutable, with side-effect-free methods returning new instances.
* **Common Mistakes**: Mutating `this.amount` inside `add()` instead of returning a new `Money` object.

# Step 7 — Engineering Insight

### Eliminating Primitive Obsession
Why pass `Money price` instead of `double price`?

* **Primitive Obsession (Anti-Pattern)**: Using `double` for currency, `String` for emails, or `int` for IDs. Every method accepting these primitives must write duplicate validation checks (`if amount < 0`).
* **Value Object Solution**: Encapsulate validation inside `Money` or `EmailAddress` constructor once. Downstream methods can accept `Money` with 100% confidence that its value is valid, eliminating defensive checks throughout your application codebase!

In **JDK `java.math.BigDecimal` & `java.time.LocalDate`**:
* `BigDecimal` and `LocalDate` are classic Value Objects.
* Calling `date.plusDays(5)` or `decimal.add(other)` leaves the original object untouched and returns a new immutable instance, ensuring thread safety and zero side effects.
